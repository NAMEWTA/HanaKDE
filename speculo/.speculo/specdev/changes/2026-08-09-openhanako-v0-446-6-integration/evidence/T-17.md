## 1. Implementation Summary

The renderer now has one pure, closed projection contract. A file-change fact is
accepted only when it contains an opaque conversation/session id, a UUIDv4
operation id, and a validated source-relative Knowledge address. The projector
requires an exact activity operation and the renderer-local workspace lifetime
before it returns either `main-history` or `operation-impact`. Foreign
conversations, stale scope generations, raw paths, Agent ids, unknown fields,
and missing correlations return `null`.

History reconstruction sanitizes the optional fact before it reaches chat
blocks. The existing Agent activity bucket locally stamps valid operation
records with the current Knowledge session epoch and preserves that stamp on
updates. Chat renders T-16's existing `FileHistoryEntryButton` only for the
`main-history` projection; T-16 remains the sole timeline/diff/restore owner.
`file-change-events.ts` remains its intentional no-op, so this ticket adds no
watcher or duplicate subscription owner.

The current ActivityHub and chat history producers do not emit the required
fact envelope or operation id. Therefore production payloads remain
operation-only/no-link until their owning read-only paths provide explicit
correlation. The implementation does not infer from `agentId`, `filePath`, or
any raw locator.
