## Deviation D-T15-04: Content-Bound Restore Authority

- **Level / approval:** ticket / Root Lead approved at `2026-08-10T16:29:40+0800`.
- **Trigger and evidence:** `opaqueVersionToken()` presently derives only from public `ResourceVersion` metadata, while `FileHistoryStore.recordSnapshot()` treats a repeated version token as interchangeable with a repeated content hash. A same-size, same-mtime replacement can therefore masquerade as the UI-observed current version and pass restore preflight, contrary to AC-016.
- **Affected authority chain:** current-token minting and restore preflight in `core/workspace-runtime/production-workspace-runtime.ts`; dedupe in `lib/file-history/history-store.ts`; read-proof and scope-root preservation in `lib/resource-io/resource-refs.ts`; proof comparison in `lib/resource-io/providers/local-fs-provider.ts`; and the existing internal runner seam in `lib/resource-io/native-secure-write.ts`.
- **Options considered:** retain metadata-only token and weaken the test (rejected: violates AC-016); add a route-visible native identity/public API (rejected: leaks capability and expands the contract); bind the opaque token to bounded bytes and preserve the private proof through the existing provider boundary (selected).
- **Approved scope:** mint `sha256(version fields + bounded content bytes)` tokens; dedupe only by content hash; fresh main-scoped bounded read immediately before restore; preserve non-enumerable WeakSet-attested `RESOURCE_READ_PROOF` and `RESOURCE_SCOPE_ROOT` across ref normalization; require its exact identity at provider preflight; let the native proof close any subsequent swap. No raw root, content proof, native identity, or symbol payload crosses the route/UI/event boundary.
- **Handling:** all D-T15-04 production edits paused until this record is committed. Existing red tests remain held in the worktree, are not part of this governance commit, and must be driven red then green before the native helper can be extended.
- **Required verification:** content-only History dedupe; different opaque tokens for equal public mtime/size with different bytes; stale UI token rejects same-size/mtime replacement without touching either current or displaced file; proof-bearing completed read rejects replacement before provider preflight with no write.

## Design It Twice: Native Conditional Write

**Problem space:** The module must preserve the existing `ResourceIO.writeExpectedVersion` caller contract while binding a local target to its root, ancestor, final-file identity, and version at the write effect. Its dependencies are local replaceable process execution (the native helper during tests), platform-owned filesystem primitives (macOS `openat` / Windows handle traversal), and in-process provider proof capture. No route, UI, or ResourceIO public contract may receive a raw helper path, filesystem identity, or proof.

**Selected A/B/C hybrid:** Caller-optimized C keeps `LocalFsProvider.writeExpectedVersion` as the only caller seam and delegates once. Minimal A makes `secureConditionalWrite(ref, content, expectedVersion)` the runner's one internal operation/result union. The real B seam injects or replaces `NativeConditionalWriteRunner` only inside that module for deterministic fixture failures; production uses the helper adapter. The LocalFs provider captures an opaque root/ancestor/final proof and attaches it only through a symbol plus `WeakMap` seam before delegation. The runner serializes exactly one bounded request frame, runs exactly one helper, accepts exactly one bounded response frame, and returns one of `written`, `conflict`, `unsafe`, `unavailable`, or `protocol-failure`. The helper receives only the physical root, validated path segments, expected native identities/version, and content bytes; it owns all handle-relative traversal and writes from the verified final handle. This gives callers high leverage while concentrating all framing and native behavior in one module.

**Candidate B - rejected:** Expose separate `openVerifiedRoot`, `openVerifiedChild`, `verifyTarget`, and `writeHandle` operations. It would leak platform handles and sequencing constraints to the provider, making the interface shallow and multiplying TOCTOU-sensitive call sites.

**Candidate C - rejected:** Generalize a `SecureFsClient` with probe/read/write/delete operations. It adds capability surface beyond the Ticket and duplicates ResourceIO authority instead of solving this one conditional-write seam.

**Private seams and typed mapping:** Process spawning/path resolution remain private runner seams so focused tests can substitute a fixture executable without changing callers. `conflict` becomes the existing `ok: false, conflict: true` result; stale identity/root/ancestor/final-link proofs map to a safe `resource_version_conflict` or `resource_access_denied` failure without a path; helper absence/unsupported state maps to `provider_not_available`; malformed, oversized, duplicate, or nonterminal frames map to a safe `secure_write_protocol_error`. No helper stderr, absolute path, or content is surfaced or logged.
