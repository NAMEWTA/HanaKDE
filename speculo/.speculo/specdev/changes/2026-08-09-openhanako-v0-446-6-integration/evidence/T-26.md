## 1. Delivered behavior

Each built-in Pi `write` or `edit` invocation now freezes one UUIDv4 operation
identity and its current session identity. An invocation-local
`AsyncLocalStorage` capture records only successful `ResourceIO.write`
mutation receipts. A fact is attempted only when exactly one receipt exists.

The production workspace runtime revalidates the current healthy main root and
derives the source-relative address from `ResourceMutationResult.resource`.
Tool arguments, SessionFile paths, cwd, Agent id and raw roots never become
History authority. The Engine then writes a non-persistent `agent_tool`
ActivityHub correlation and returns the closed T-17 fact. The existing
SessionFile card carries that fact through the normal write/edit block
extractor and `/sessions/messages` reconstruction.

The desktop session factory now supplies its already-owned session path to the
existing `buildTools` callback. On renderer reload, the first authorized
websocket subscription to that session triggers one replay of existing
in-memory activity; repeated messages do not replay. A server restart clears
the activity, so the persisted fact remains fail-closed and link-free.
