## 1. 实现摘要

The root dependency gate now verifies production runtime exports and a real Pi
AI import before postinstall/start paths proceed. The packaged server reuses
the shared verifier with its narrower contract. Desktop startup distinguishes
source dependency failures from packaged component failures, permits exactly
one packaged retry, then offers user-confirmed artifact repair. Optional JSON
uses fallback only for ENOENT while keeping malformed JSON and other I/O
failures observable.

After synchronizing `origin/hanakde`, the new built-in todolist plugin exposed
a packaging drift: its root `build.ts` imports dev-only `esbuild`. The
runtime graph now excludes only conventional plugin-root
`plugins/<id>/build.[cm]?[jt]s` entrypoints. A red/green regression proves a
nested `plugins/<id>/src/build.ts` remains a runtime entry, preventing the
filter from hiding legitimate nested code.

The real packaged plugin dependency set is:
`@firecrawl/anydoc`, `@lezer/markdown`, `better-sqlite3`, `exceljs`,
`js-yaml`, `mammoth` and `unpdf`; it does not contain `esbuild`.
