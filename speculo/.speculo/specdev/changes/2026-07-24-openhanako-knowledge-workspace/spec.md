## V1 核心范围与现行规则

### Workspace、来源与地址

- 当前工作目录就是唯一 workspace 的 `main`；切换目录表示打开全新 workspace，旧挂载全部卸载。
- `main` 与每个挂载源都是彼此隔离的内容来源，拥有独立文件空间、知识地址空间、链接图、反向引用域、标签域和同源重构边界。
- `sourceKey` 仅用于应用内部 KnowledgeResourceAddress、API、会话和搜索分组；底层 provider 引用继续使用既有 ResourceRef。Markdown Wikilink 只保存当前来源内的规范相对路径与真实扩展名。
- 来源内地址解析不得跨越来源根，也不得搜索其他挂载源作为回退。来源根必须经 ResourceIO/provider 证明不重叠。
- V1 每次打开工作目录都使用空白默认界面，不恢复布局、标签、资源树状态、未保存缓冲区或挂载。
- 用户显式重选完全相同的历史来源根时可以复用未占用的 `sourceKey`/`displayName`；key 冲突时要求选择新 key 或先处理占用来源，不提供复杂 key 交换和正文迁移。

### 链接、来源丢失与保存

- Wikilink、嵌入、内容引用、Markdown 内部文件链接、出站引用和反向引用都只能存在于同一来源内。
- 同来源资源直接写相对于来源根的 `[[relative/path.ext]]` 或 `![[relative/path.ext]]`；Markdown 中禁止 `sourceKey:` 跨来源地址。
- 当当前页面需要使用另一来源资源时，必须先把整个文件复制到当前来源，再引用副本；复制保持文件正文原样，不自动修订内部链接。
- 同来源页面、资产或目录移动及重命名仍可执行同源原子地址重构；跨来源只允许普通复制，不提供迁移、复制后自动删除或跨来源重构。
- 来源丢失时，干净文档保留当前会话占位；脏文档不可逆地转为悬空未保存文档。另存按新建页面并保持正文原样。
- 切换 workspace 先预检候选目录，再处理未保存文档，最后提交关闭旧 workspace。

### V1 功能和索引边界

- V1 延后收藏、最近、全局任务视图、独立标签视图和跨文件标签维护。
- 保留页面内任务、标签解析、当前页面大纲、同源出站引用和同源反向引用。
- 每个来源维护独立的可重建索引。超级搜索可以查询全部当前来源，但结果必须按来源顶层分组；搜索不得被链接解析器用来猜测跨来源目标。
- 超级搜索、标签索引、反向引用和搜索片段只读取成功保存的磁盘内容；当前大纲与出站引用可读取当前页面未保存缓冲区。
- 来源组顺序为 `main` 后接本会话挂载顺序；每组内部按相关性与规范相对路径稳定排序。

## 问题陈述

OpenHanako 当前具备工作目录、资源访问、预览编辑、挂载与资源事件等基础能力，但这些能力尚未形成一套完整、可预期且适合长期知识工作的闭环。用户在真实目录中组织 Markdown 页面与任意资产时，仍可能需要在文件管理器、编辑器、搜索工具和外部应用之间反复切换；同一资源的打开、保存、移动、引用修复、外部冲突、回收与恢复也缺少统一语义。多来源目录、分屏编辑、同一页面多视图、知识链接、页面属性、标签、任务和全文检索若分别实现，很容易产生第二套文件系统、第二个编辑器内核、重复索引、路径泄露或不可恢复的数据操作。

用户需要的是忠实于真实磁盘、兼容 Finder/Git/脚本/其他编辑器、又能提供现代知识编辑体验的统一知识工作区。它必须在不牺牲 OpenHanako 原有架构、安全边界、独立 Server、LAN/Mobile 能力和用户数据可移植性的前提下，把文件资源管理器与 Markdown 编辑器做成可靠核心，并让链接、索引、搜索、回收站和多视图状态都围绕同一知识事实工作。

## 解决方案

在“知识”一级入口中提供由一个主来源 `main` 和零个或多个额外挂载源组成的工作区。资源树统一呈现这些真实目录，但每个来源在知识语义上等同独立工作区：链接、嵌入、反向引用、标签关系、延迟建页和资源地址重构都不能越过来源边界。

应用内部通过 KnowledgeResourceAddress `{sourceKey, relativePath}` 区分资源，由 Server 映射到既有 ResourceRef；Markdown 源码只保存来源内规范相对路径。用户把另一来源的 Page 或 Asset 插入当前 Markdown 时，OpenHanako 先按普通文件复制规则把整个文件复制到当前来源，再插入指向副本的来源内 Wikilink。复制不分析或改写文件正文；副本中的链接在新来源内按原文字重新解析，失效位置由用户自行修订。

同一来源内继续支持真实资源树、CM6 Markdown 编辑、页面大纲、同源链接与嵌入、同源移动/重命名重构和来源级回收站。超级搜索可以查询所有当前来源，但按来源分组并保持索引隔离。所有文件操作继续复用 Workbench、ResourceIO 和资源事件链路；磁盘文件始终是唯一知识事实。

## 用户故事

以下用户故事覆盖主流程、边界情况、错误处理、权限与角色、状态转换及跨平台行为。

### 工作区、来源与资源身份

1. **KW-US-001** — 作为用户，我希望当前工作目录成为 `main`，并可挂载其他真实目录用于浏览、编辑、搜索和复制。
2. **KW-US-002** — 作为重视边界的用户，我希望 `main` 与每个挂载源彼此隔离，以便一个来源中的链接、标签和反向引用不会意外关联另一来源。
3. **KW-US-003** — 作为 Markdown 用户，我希望 Wikilink 只保存来源内规范相对路径，以便文件脱离 OpenHanako 后仍能在单个目录树中理解。
4. **KW-US-004** — 作为多来源用户，我希望应用内部仍用 `sourceKey` 区分同名资源，但该 key 不污染 Markdown 正文。
5. **KW-US-005** — 作为跨来源使用资料的用户，我希望将另一来源文件插入当前页面时先复制整个文件，再链接副本，以便来源之间不存在隐式依赖。
6. **KW-US-006** — 作为可移植性用户，我希望复制保持文件正文原样，链接失效时由我访问后自行修订，而不是应用批量猜测。
7. **KW-US-007** — 作为安全用户，我希望来源根真实路径不能重叠，路径解析永远不能越过当前来源 scope。
8. **KW-US-008** — 作为重新挂载用户，我希望显式重选相同历史根时可以复用未占用的内部来源身份，但冲突时必须明确选择新的 key。
9. **KW-US-009** — 作为隐私敏感用户，我希望远程 DTO 和 UI 不暴露不必要的本地绝对路径。
10. **KW-US-010** — 作为多平台用户，我希望 Desktop、独立 Server、LAN 与 Mobile 对来源隔离和复制规则保持一致。

### 知识视图、资源树与导航

11. **KW-US-011** — 作为知识工作者，我希望从与聊天同级的知识视图进入完整知识工作区，以便集中浏览、组织和编辑长期资料。
12. **KW-US-012** — 作为资源树用户，我希望看到主根目录与每个挂载源的真实文件夹、页面和资产，以便界面结构与磁盘结构保持一致。
13. **KW-US-013** — 作为文件管理用户，我希望在资源树、编辑器标签、搜索结果和文件操作界面中看到完整原始文件名及扩展名，以便不会把不同格式或未知后缀误认为同一资源。
14. **KW-US-014** — 作为浏览文件夹的用户，我希望单击文件夹只选择，点击箭头或双击才展开或折叠，以便能稳定选择文件操作目标而不意外改变树结构。
15. **KW-US-015** — 作为键盘用户，我希望用上下方向键在当前可见节点间单选导航，以便无需鼠标即可高效定位资源。
16. **KW-US-016** — 作为键盘用户，我希望用左键折叠或返回父目录、用右键展开或进入首个可见子节点，以便获得符合桌面文件树习惯的层级导航。
17. **KW-US-017** — 作为批量操作用户，我希望用 Shift 加方向键从固定锚点扩展或收缩连续范围，以便能够准确选择当前可见的连续资源。
18. **KW-US-018** — 作为批量操作用户，我希望用 Ctrl/Cmd 加方向键只移动焦点，并用 Ctrl/Cmd+Space 切换非连续选择，以便可以建立不连续选择而不破坏已有集合。
19. **KW-US-019** — 作为安全操作用户，我希望让一次资源树选择集只能属于一个内容来源，以便批量操作始终有单一来源、回收站和移动语义。
20. **KW-US-020** — 作为安全操作用户，我希望在选择包含文件夹及其后代时自动只保留最外层祖先，以便同一磁盘对象不会被重复处理。
21. **KW-US-021** — 作为资源树用户，我希望右键已选节点时保留选择集，右键未选节点时先单选该节点，以便上下文菜单总是作用于可解释的对象。
22. **KW-US-022** — 作为资源树用户，我希望点击空白区域清除选择，以便能够明确结束当前批量操作上下文。
23. **KW-US-023** — 作为快速浏览用户，我希望在文件节点上按 Space 打开或激活临时预览且焦点留在资源树，以便连续查看资源时不会制造大量固定标签。
24. **KW-US-024** — 作为固定工作用户，我希望在文件节点上按 Enter 固定打开并把焦点交给内容视图，以便可以从浏览状态进入稳定编辑状态。
25. **KW-US-025** — 作为文件夹导航用户，我希望在来源根或文件夹上按 Enter 只切换展开状态，以便不会生成没有内容语义的文件夹标签。
26. **KW-US-026** — 作为重命名用户，我希望用 F2 或右键在原树行内编辑单个资源的完整名称，以便可以快速改名且仍经过同源资源地址重构。
27. **KW-US-027** — 作为重命名 Markdown 文件的用户，我希望默认只选中最后扩展名前的基本名称，以便改标题时不容易误删 `.md` 扩展名。
28. **KW-US-028** — 作为使用多个编辑入口的用户，我希望让活动文档变化不自动展开、滚动或改选资源树，以便资源树选择不会因阅读链接或搜索结果而被破坏。
29. **KW-US-029** — 作为需要定位文件的用户，我希望通过路径面包屑或“在资源树中显示”显式展开祖先并单选资源，以便可按需回到真实文件位置。
30. **KW-US-030** — 作为长期使用深层目录的用户，我希望当前 workspace 会话内保留已展开文件夹，以便连续导航；关闭或重新打开 workspace 后从折叠默认状态开始。
31. **KW-US-031** — 作为排序资源的用户，我希望按名称、最后修改时间或扩展名排序文件，并切换升降序，以便可按当前任务快速组织视图。
32. **KW-US-032** — 作为依赖稳定目录骨架的用户，我希望让文件夹在所有排序模式中始终优先并按自然名称升序，以便切换文件排序时目录位置不会跳动。
33. **KW-US-033** — 作为多来源用户，我希望排序模式只在当前 workspace 会话内生效，以便 V1 不建立跨打开的来源 UI 状态恢复。
34. **KW-US-034** — 作为重新打开 workspace 的用户，我希望不恢复资源树选择、范围锚点和键盘焦点，以便避免对已经变化的资源误执行操作。

### 创建、导入、复制、移动与拖拽

本领域的用户故事由前后相邻条目覆盖，并遵守以下冻结规则：

- V1 直接创建 Markdown Page 与文件夹，其他文件通过导入进入指定来源。
- 同一来源内拖拽、剪切粘贴和重命名可以执行普通移动，并对同源可确定链接进行原子重构。
- 跨来源拖拽和复制粘贴只创建普通副本；原资源保持不变。
- V1 不提供跨来源迁移、“移动到来源”、复制后自动删除或跨来源剪切粘贴。
- 所有复制保持文件正文/字节内容原样，不扫描、不修订 Wikilink、Markdown 链接或嵌入。
- 跨来源 Page 插入编辑器时复制到当前 Page 目录；资产插入时复制到同级 `assets/`。
- 名称冲突沿用确定性后缀和资源级原子、批次级部分完成规则。
- 用户需要移除原件时，必须在原来源中另行执行删除并经过来源级回收站。

### 索引、超级搜索、标签与任务

本领域的用户故事由前后相邻条目覆盖，并遵守以下冻结规则：

- 每个来源建立独立、可重建的搜索、标签和引用索引。
- 超级搜索可查询全部当前来源，但结果第一层按来源分组：`main` 首位，其余按挂载顺序。
- 每个来源组内按资源聚合命中并独立计算相关性；同名资源和标签不跨来源合并。
- 搜索只读取已保存磁盘内容，不读取未保存缓冲区或最近记录。
- 点击搜索结果可以打开其来源资源；将结果插入另一来源 Markdown 时必须先复制。
- 标签点击只在当前来源内发起预填搜索，并在搜索界面显示不可编辑的当前来源上下文；V1 不提供跨来源标签关系或通用来源筛选器。
- 出站引用从当前缓冲区解析但只产生同源边；反向引用只查询当前来源已保存索引。
- 页面内标准任务继续支持；全局任务视图、收藏、最近和独立标签视图延后。

## 实现决策

### 1. 需求优先级与产品边界

1. V1 的绝对核心是文件资源管理器与 Markdown 编辑器；基础超级搜索保留，搜索筛选器、任务高级元数据和其他知识增强工具不扩张 V1 范围。（ADR-0033、ADR-0283）
2. “知识”是与“聊天”“频道”同级的一级入口；聊天中的工作台是同一知识工作区的紧凑视图，不建立第二套目录或副本。（基础 `ADR-0001`；仓库级细化 `ADR-0284`）
3. 知识工作区由一个主根目录和零个或多个具名挂载源组成；来源身份不扁平合并。（基础 `ADR-0002`；仓库级细化 `ADR-0285`）
4. 页面身份与知识地址采用“来源身份 + 规范化相对路径”；页面、资产或目录移动及重命名会改变受影响资源身份，不引入隐藏 UUID。（基础 `ADR-0003`；仓库级细化 `ADR-0286`、`ADR-0289`）
5. 磁盘页面与资产是唯一知识事实；索引、反向引用、标签、任务和属性视图全部可丢弃、可重建。（基础 `ADR-0006`；仓库级细化 `ADR-0288`、`ADR-0297`）
6. 当前项目工作树是唯一开发底座；本地 SilverBullet 源码 `./silverbullet/` 仅提供可独立研究和适配的 CM6、Live Preview、受控空间、解析和索引思路，不移植 Preact 产品 UI、Rust Server、Lua/查询语言、插件运行时或对象数据库。（基础 `ADR-0262`、`ADR-0283`；仓库级细化 `ADR-0299`）

### 2. 架构分层与依赖方向

1. Renderer 负责 React UI、CM6 表面、前端 service、文档会话投影和视图状态；不得直接访问 Node 文件系统、Server 私有实现或 Engine 私有状态。
2. 普通输入和编辑事务完全留在 Renderer；它们不得产生 HTTP、WebSocket、IPC 或 Hub 往返。
3. Workbench 继续负责工作目录、挂载来源与现有兼容入口；ResourceIO 继续负责通用资源读取、列举、搜索、expected-version 写入、移动、重命名、回收和 watcher。
4. 只有单次 ResourceIO 无法表达的复合知识事务进入知识工作区领域编排，包括操作预览/提交、原子链接重构、跨来源复制、索引编排和工作区回收站恢复。
5. Engine 保持薄 Facade，仅公开委托、组合和生命周期能力；可变领域状态由明确 Manager、Coordinator、Registry 或 Store 持有。
6. Server route 只负责认证、schema 校验、scope/owner 检查、调用 Engine 公开 API、状态码和稳定错误映射；不得实现解析、索引、事务算法或直接访问私有字段。
7. `shared` 只承载可序列化 DTO、schema、协议版本和稳定错误码；不得引入 React、CM6、Hono、Electron、Manager 或不可序列化对象。
8. `lib` 领域模块只承载可复用纯算法与数据结构，包括知识地址、Markdown 链接解析与重写、Frontmatter、操作计划、搜索索引、索引存储和回收站 manifest。
9. Electron main/preload 只补充系统文件选择器、系统文件剪贴板、系统废纸篓、默认应用和“在文件管理器中显示”等必须由本机完成的能力；普通文件 CRUD 不走 IPC。
10. 不新增顶级知识应用、独立知识 Server、第二套文件系统、第二条资源事件 WebSocket、第二个 watcher 或与现有目录平行的大型 Renderer 根目录。

### 3. 状态真相与生命周期

1. 磁盘中的页面和资产内容属于持久知识事实；Renderer 中未保存源码只属于当前页面编辑会话。
2. 同一 Markdown 文档的共享会话持有源码、最近成功读取/保存基线、版本、未保存状态、撤销历史、保存中状态、冲突状态和视图引用计数。（ADR-0212、ADR-0225—ADR-0233）
3. 每个文档视图独立持有光标、选区、滚动、视口、实时预览/源码模式、Live Preview 语法显隐和当前文档查找状态。（ADR-0213—ADR-0216、ADR-0219—ADR-0224）
4. V1 不持久化 workspace 界面状态；每次打开工作目录使用单个空编辑组、空标签和折叠资源树。当前会话内的标签、布局、选择与展开仅存在于内存。
5. 资源树展开状态和排序模式/方向只在当前 workspace 会话内存在；关闭或重新打开后不恢复。
6. ResourceIO version/mtime 是磁盘并发事实；资源事件总线与既有 WebSocket 是外部变化的唯一实时通知链路。
7. 知识索引是 Server/Core 持有的可重建缓存；操作计划是短生命周期对象，提交前必须重新验证版本和前置条件。
8. 最后一个文档视图释放后，页面共享缓冲区和撤销历史一并释放；重新打开创建新视图和新会话初始状态。

### 4. Renderer 与 CodeMirror 6

1. 从现有 PreviewEditor 渐进抽取单一 MarkdownEditorSurface 和稳定 extension factory；Preview 与知识编辑器必须组合同一 CM6 内核，禁止复制第二套完整编辑器。
2. CM6 生命周期、EditorState、EditorView、transaction、Compartment、事件监听和销毁集中管理；组件卸载必须释放所有 view、listener、observer 和 subscription。
3. 每个 extension 只承担一个清晰职责；视图装饰与纯 Markdown 解析分离；extension 不直接调用 Server、Zustand 全局实例或 Electron。
4. Live Preview 仅隐藏未被光标或选区触及的语法；实时预览与源码模式共享同一 Markdown 文本和撤销历史。（ADR-0009、ADR-0067）
5. Markdown 解析基线为 CommonMark、GFM 与已确认扩展；页面应用内编辑只接受严格 UTF-8，原始文件大小上限为 10 MiB。（ADR-0063、ADR-0064、ADR-0139）
6. 保存保留单一既有换行风格；混合换行按确定性规则规范化，避免平台噪声 diff。（ADR-0065）
7. 列表、任务、引用延续、Tab 行级缩进、有序列表编号延续、围栏代码块 Tab 和普通 Markdown Tab 行为按 ADR-0068—ADR-0072 实现。
8. V1 基础格式快捷键与斜杠命令共享同一编辑语义；命令任意位置触发、查询止于第一个空白、采用固定单层列表与最小模板。（ADR-0073—ADR-0076、ADR-0078—ADR-0085）
9. Mermaid、数学、脚注、净化 HTML、本地资产、外链打开、附件、Wikilink 补全、页面嵌入、表格和代码块按对应 ADR 实现；任何预览错误以内联状态呈现，不替换或破坏源码。
10. 视觉软换行只影响显示，所有方向键、Home/End、Shift 选择、坐标和编辑行为按真实源码位置执行。（ADR-0142—ADR-0147）
11. 全局底部状态栏只读显示活动 Markdown 视图的 1 基行列与源码 Unicode 字符总数；不显示保存状态，非 Markdown 视图保留空单行，空间不足时整组隐藏。（ADR-0148—ADR-0159）
12. 当前文档查找替换严格冻结 ADR-0161—ADR-0205、ADR-0207—ADR-0211：匹配真实源码、默认忽略大小写、可切换全词、不支持正则、循环导航、单一右上角弹窗、全部匹配高亮、替换全部为单一撤销步骤、无历史与 F3 快捷键。
13. 大文档解析和索引请求必须可取消、分阶段或增量；不得在每次 transaction 中全量扫描整个工作区，也不得在 React render 中反复重建 extension 集。

### 5. 资源树、标签与布局

1. 资源树一比一呈现真实来源根、文件夹、页面和资产；文件节点始终显示完整原始文件名及扩展名。（ADR-0005、ADR-0045、ADR-0046）
2. 文件夹单击只选择，独立箭头或双击切换展开；文件夹不创建编辑器标签或内容页。（ADR-0035）
3. 页面和资产普通打开先在所有编辑组全局查找既有标签；单击使用/激活临时预览，双击固定；只有显式侧边打开或分屏才创建额外视图。（ADR-0034）
4. 每个编辑组最多一个临时预览标签；开始编辑、明确固定或拖动即原地转为固定标签。
5. 编辑器标签使用完整文件名；每个编辑组在标签栏下显示一条来源相对路径面包屑，路径段只负责显式定位资源树。（ADR-0046—ADR-0048）
6. 资源树选择支持单选、Ctrl/Cmd 非连续选择、Shift 连续选择和完整键盘导航；一次选择集限制在一个来源，执行操作前删除被已选祖先覆盖的后代。（ADR-0036、ADR-0258—ADR-0261）
7. F2/右键只允许单项行内重命名；来源根不可行内重命名，V1 不支持批量重命名。（ADR-0264）
8. 资源树不自动跟随活动文档；只有树操作、面包屑或显式“在资源树中显示”才展开祖先并单选目标。（ADR-0048）
9. 排序提供名称、mtime、扩展名及方向；文件夹始终优先且自然名称升序，当前模式只作用于文件组，状态按来源记忆。（ADR-0037）
10. V1 不恢复编辑布局、固定标签或来源展开状态；来源在当前会话中丢失时，干净页面占位等待重载，脏页面转为悬空未保存文档。

### 6. 页面、资产、链接与嵌入

- 应用内部 KnowledgeResourceAddress 使用 `{sourceKey, relativePath}`，由 Server 来源注册表映射为既有 ResourceRef；Markdown Wikilink 只使用来源内规范相对路径。
- LinkResolver 必须接收引用页面的 `sourceKey`，并强制目标保持在同一来源；不得查询其他来源作为回退。
- Wikilink 补全和延迟建页只访问当前来源。
- 同源移动/重命名可以调用链接重构；跨来源复制不调用任何链接分析或重写。
- 编辑器跨来源插入通过“复制文件成功 → 生成副本本地地址 → 插入链接”完成。
- Page 嵌入、资产嵌入、内容引用、出站引用和反向引用均为同源能力。

### 7. 保存、并发、冲突与关闭

1. V1 使用显式手动保存；Ctrl/Cmd+S 只保存当前活动 Markdown 文档，不自动保存、不提供“保存全部”。（ADR-0251、ADR-0253）
2. 保存使用当前共享源码与最近成功版本执行 expected-version 写入；成功静默且不清空撤销历史。（ADR-0225、ADR-0228）
3. 保存失败不回滚源码，所有视图保持未保存；同一文档复用一条非模态、持久、可手动关闭的错误通知，后续成功自动清除。（ADR-0227—ADR-0232）
4. 外部变化在本地干净时自动重载；本地脏时保留基线、本地、磁盘三方并要求用户明确合并、使用本地或使用磁盘。（ADR-0011）
5. 来源丢失后，脏页面不可逆地转为悬空未保存文档；来源恢复也不自动重新绑定。
6. 悬空文档保存严格按新建页面处理：在当前 workspace 的可用可写来源内选择新 Page 路径并绑定新身份，不改写任何指向旧地址的引用；工作区外路径不属于该保存流程。
7. 不建立后台等待重连、自动迁移、三方恢复或普通未保存缓冲区恢复机制。
8. 关闭非最后视图直接完成；关闭最后一个未保存视图提供保存、放弃、取消。（ADR-0240—ADR-0241）
9. 退出或关闭工作区按文档逐个执行同一流程；任何取消或保存失败立即终止整体关闭，已完成结果不回滚。（ADR-0240—ADR-0250）
10. 普通未保存输入不建立定时恢复副本；只在同源资源地址重构、Agent 修改、冲突覆盖、恢复和删除前建立高风险本地检查点。（ADR-0257）

### 8. 文件操作、事务与失败模型

- 同源移动/重命名是文件变化与同源可确定引用更新的复合事务。
- 普通复制只保证文件系统结果；正文保持原样，链接状态不影响复制成功。
- 跨来源操作只能复制；不提供迁移事务或自动删除源资源。
- 编辑器复制并插入链接时，复制必须先成功，随后才修改 Markdown 缓冲区。
- 删除与恢复继续限定在单一来源的回收站和索引边界内。
- 多资源操作保持资源级原子、批次级部分完成。

### 9. 回收站

1. 主根和每个挂载源在来源根级维护独立工作区回收站；正常资源树、索引、搜索、标签、任务和引用解析必须排除其内容。（ADR-0015）
2. 删除始终确认，并在删除前逐个解决受影响未保存 Markdown 文档。
3. 删除批次记录来源、原相对路径、删除时间和恢复所需 manifest；删除、恢复、清理均采用资源级原子和批次级部分完成。
4. 恢复固定返回原位置，缺失父目录可安全重建；名称冲突用 `_2`、`_3`，目录作为整体避让。
5. 只修复同一删除批次内部且双方都恢复的可确定引用；工作区其他断裂引用保持原文。
6. 默认保留 30 天；到期或手动清理只移入系统废纸篓，应用不提供不可恢复永久删除。（ADR-0015）

### 10. 索引与超级搜索

- 每个来源维护独立索引分区，索引键包含内部 `sourceKey`，但解析出的 Wiki 地址只保存来源内路径。
- 引用索引不得创建跨来源边。
- 超级搜索并行查询来源分区，结果按来源顶层分组；来源内部按相关性和规范路径排序。
- 搜索结果不能被 LinkResolver 用于跨来源目标猜测。
- 标签、Frontmatter、Markdown 正文和安全文本资产均只属于其真实来源分区。

### 11. 非 Markdown 资产

1. V1 不提供非 Markdown 可写缓冲区；安全文本只读预览、专用媒体/PDF 预览和文件信息视图均复用统一资产身份。（ADR-0057）
2. 无 BOM 文件仅在严格 UTF-8 完整解码时视为文本；带 BOM 的 UTF-8/16/32 按 BOM 解码，不猜测 GBK、Big5、Shift-JIS、ANSI 或系统代码页。（ADR-0060）
3. 非 Markdown 文本预览与正文索引共享 10 MiB 原始大小上限；超限时只保留资源身份搜索和系统默认应用入口。（ADR-0062）
4. 资产外部变化自动刷新只读预览并尽量恢复稳定上下文；失败时保留标签和手动重新加载，路径消失时显示“资源不存在”且不猜测新位置。（ADR-0058）
5. 是否可预览不影响导入、复制、移动、重命名、删除、引用和当前会话中的资源失效占位能力。

### 12. API 契约与错误模型

1. 跨层契约至少包含知识地址、知识资源、操作预览、操作提交、每项批次结果、搜索请求/结果、回收站条目、索引状态和协议版本。
2. 知识资源 DTO 只传递稳定来源身份、规范化相对路径、资源类型、名称、版本、mtime、大小和必要能力标记；不传递任意绝对路径、DOM、EditorView 或文件句柄。
3. 复合操作采用“预览计划—用户确认—带计划标识和前置版本提交”的两阶段语义；提交必须重新验证 owner、scope、版本、资源存在性和目标冲突。
4. 批次结果使用每项判别联合或结构化 successes/failures，不能以一个含义不明的布尔值掩盖部分完成。
5. 客户端分支只能依赖稳定错误码，不依赖异常文案。至少保留：`knowledge-resource-not-found`、`knowledge-resource-conflict`、`knowledge-version-conflict`、`knowledge-resource-out-of-scope`、`knowledge-operation-plan-expired`、`knowledge-operation-precondition-failed`、`knowledge-link-rewrite-failed`、`knowledge-index-unavailable`、`knowledge-trash-entry-not-found`、`knowledge-trash-parent-blocked`、`knowledge-native-capability-unavailable`。
6. HTTP、WebSocket、preload、配置、磁盘旧数据和 Provider 返回值一律先视为 `unknown`，经 schema 校验后进入领域类型；新代码不使用 `any` 或双重断言隐藏协议不兼容。
7. WebSocket 事件必须版本化；断线重连后通过快照、事件回放或重新查询恢复，而不是假定页面持续打开。

### 13. 安全、兼容、性能与国际化

1. 所有资源访问必须经过现有 PathGuard、ResourceIO、sandbox policy、owner 和来源 scope 校验；权限、文件、远程访问和原生能力默认 fail-closed。
2. Renderer 不使用 Node.js API；Server 保持独立 Node.js 进程，不依赖 Electron 内存或模块。
3. 外部 URL 只允许经校验的 HTTP/HTTPS，并验证协议、host、重定向、响应大小和超时；禁止 SSRF 和自动外链加载。
4. 日志不得记录 token、API key、cookie、authorization header、任意用户正文或不必要绝对路径；错误响应使用净化后的稳定信息。
5. Open/Full 差异只在 composition root 注入；开放代码不得动态 import 或路径拼接私有实现。
6. 保持现有 Workbench、ResourceIO、资源事件、Desktop、Mobile、LAN、CLI 和旧客户端兼容；已有兼容路由不因知识工作区引入而删除或改变含义。
7. V1 不新增 workspace UI 状态持久化；索引格式、回收站 manifest 或协议变化仍必须有幂等、可恢复迁移和旧数据读取测试。
8. 新 UI 必须覆盖中文、英文、日文、韩文和繁体中文，支持亮/暗主题、多窗口、键盘访问、焦点管理和辅助技术语义。
9. 文件名大小写、Unicode、符号链接、换行、废纸篓和原生能力必须覆盖 Windows、macOS、Linux 差异。
10. 解析、搜索、预览和复制必须有大小、超时、取消与并发限制；性能优化不得绕过状态真相、安全边界或事务正确性。

### 14. 分阶段实施

1. **Phase 0：契约保护。** 固化现有 ResourceIO、Workbench、资源事件、open/full boundary 与旧客户端兼容测试。
2. **Phase 1：CM6 内核抽取。** 从现有编辑器抽取共享表面、extension factory 和生命周期；保持现有预览行为不回归。
3. **Phase 2：Renderer 资源客户端。** 集中 ResourceIO/知识复合操作客户端、取消、DTO 校验、错误映射和 WS 恢复。
4. **Phase 3：文档会话与编辑组。** 实现共享文档缓冲区、多视图、标签、递归布局、会话内状态、保存与冲突；不实现 workspace UI 恢复。
5. **Phase 4：真实文件资源管理器。** 实现来源树、选择、键盘、排序、新建、导入、内部剪贴和拖拽基础。
6. **Phase 5：来源隔离知识操作。** 实现同源地址解析、同源移动/重命名重构、跨来源普通复制，以及复制后插入来源内链接。
7. **Phase 6：索引、超级搜索和回收站。** 实现可重建索引、统一搜索、来源级回收站、恢复和清理。
8. **Phase 7：收敛。** 完成多平台、open/full、LAN/Mobile、国际化、可访问性、性能、迁移和回归验证。
9. 每一阶段必须保持主分支可构建、既有 Workbench/Preview 可用，不预先创建无职责模块或空目录。


## 实施级冻结契约

以下内容不是开发者可重新选择的建议：

1. **根身份：** provider 必须实现 `ProviderRootIdentityResolver`；只有明确 `disjoint` 的来源可共存，`unknown` 拒绝。见 `implementation-contracts.md`。
2. **操作恢复：** 所有复合 mutation 使用 UUIDv7 operationId、15 分钟 plan TTL、持久 journal、幂等 commit 与启动 recovery barrier。见 `operation-journal-contract.md`。
3. **索引：** 每来源 better-sqlite3 schema v1、独立 generation、current manifest、WAL/FULL、单 writer 和无 in-place migration。见 `index-store-contract.md`。
4. **原生能力：** 复用 `window.hana`，新增两个固定 IPC；resource action 使用 60 秒单次 grant，Renderer 不获得绝对路径。见 `implementation-contracts.md`。
5. **E2E：** `@playwright/test@1.62.0`，固定 desktop-full/web-open/web-full projects 与 `E2E-KW-001`—`024`。见 `test-strategy.md`。
6. **追踪：** 每个用户故事只有一个 primary owner 和至少一个精确测试路径；Ticket 57 不拥有用户故事。见 `requirements-traceability.md`。
7. **Preflight：** Ticket 01 在真实仓库执行 implementation-preflight；关键契约漂移时先更新 change。
8. **内部目录：** index/journal/source binding 仅在 HANA_HOME；来源内只有 `.trash/` 是内部区域且从正常知识空间排除。

## 测试决策

### 测试原则

1. 测试只验证公开行为、协议、可观察状态和用户结果，不依赖 Engine 私有字段、内部文件名或脆弱实现顺序。
2. 采用“一个主接缝 + 现有支持接缝”的策略：以知识视图 UI E2E 作为最高层主接缝；API、ResourceIO、纯领域算法、WebSocket 与构建检查只补充 UI 难以稳定覆盖的安全和事务细节。
3. 优先复用当前项目现有 Vitest、route、contract、build、boundary 和平台测试模式；`silverbullet/e2e/` 中的编辑格式、页面重命名、Wiki Link 和粘贴 E2E 仅作为交互覆盖参考，不复制其测试基础设施。
4. 好测试必须能在重构实现后继续成立，并且失败信息能指向“用户行为或契约被破坏”，而不是某个私有函数调用次数变化。
5. 所有文件测试使用隔离临时来源和真实文件系统语义；不得依赖开发机固定绝对路径、用户目录或网络可用性。

### 已冻结测试接缝

完整技术栈、fixture、CI 与平台矩阵见 `test-strategy.md`；以下接缝必须映射到固定 E2E ID，不得在 Ticket 57 临时重新命名。

|---|---|---|---|---|

### 主接缝 E2E 场景

1. 以一个主根和两个同名路径挂载源启动知识视图，验证来源身份、完整文件名与面包屑。
2. 验证文件夹选择/展开分离、方向键、Shift 连选、Ctrl/Cmd 非连续选择、单来源限制、祖先规范化和空白清除。
3. 验证 Space 临时预览、Enter 固定打开、双击固定、全局标签复用和显式侧边多视图。
4. 在同一页面两个视图中编辑，验证共享源码/撤销/未保存状态与独立光标/滚动/模式。
5. 重新打开任意工作目录，验证使用单个空编辑组、空标签、折叠资源树和空挂载列表，不恢复历史 UI 状态。
6. 验证严格 UTF-8、10 MiB 边界、换行风格、Live Preview 语法按需展开、列表/Tab/快捷键/斜杠命令。
7. 覆盖 Mermaid、数学、脚注、表格、代码块、净化 HTML、本地资源和外链显式打开。
8. 覆盖查找替换全部冻结行为，包括跨标签/跨组、空查询、无匹配、替换全部单次撤销和焦点循环。
9. 验证手动保存、成功静默、失败持久通知、expected-version 冲突、三方解决，以及来源丢失后悬空文档的新建页面保存。
10. 验证最后视图关闭和应用退出的逐文档保存/放弃/取消，确认取消或失败终止后续关闭。
11. 验证新建目标判定、同名改名、导入三策略、目录合并、类型冲突、取消、摘要和仅重试失败项。
12. 验证内部复制/剪切/粘贴、确定性后缀、同名文件夹不合并、批次部分成功，以及复制正文保持原样。
13. 验证同来源拖拽移动、跨来源普通复制、跨来源剪切拒绝、有效目标、800ms 展开、边缘滚动和完成后选择/焦点。
14. 验证移动/重命名的操作预览、必要链接原子重写、任一写入失败整体回滚和外部移动不自动推断。
15. 验证删除确认、未保存文档预处理、来源级回收站、30 天清理、恢复冲突和系统废纸篓边界。
16. 验证超级搜索的来源顶层分组、组内资源聚合与排序、关键词/短语/OR 词法、Unicode 子串、定位和分区索引重建。
17. 验证资产只读预览、安全解码、超限、PDF 无正文搜索、外部刷新、资源消失和系统默认应用入口。
18. 在亮/暗主题、五种语言、键盘-only、多窗口和最窄支持宽度下执行关键流程。

### API 与领域测试重点

1. 知识地址规范化、来源隔离、大小写/Unicode 文件系统差异和绝对路径拒绝。
2. Wikilink、Markdown Link、内容引用坐标/快照/转义、Frontmatter、标签、任务、脚注、嵌入边界和循环检测。
3. 搜索词法的 Unicode 空白、转义、未闭合引号、独立全大写 OR、资源级 AND、去重与稳定排序。
4. 同源资源移动/重命名计划的版本快照、后代地址映射、写入顺序、失败注入、回滚和外部变化重验证。
5. 页面、资产和目录复制保持每个成功副本的正文或字节内容与源文件一致；不得建立链接重写集合，失败项不得产生半成品或占位引用。
6. 导入、粘贴、删除、恢复的资源级原子与批次级部分完成，确保临时文件不进入正式资源树。
7. 回收站 manifest 旧版本兼容、父目录重建、目录整体避让、批次内部引用调整和到期清理。
8. 索引全量重建与事件增量最终一致、损坏恢复、取消、超限和索引不可用降级。
9. auth、owner、scope、PathGuard、Provider sandbox、错误映射、日志净化和 fail-closed。
10. Renderer 异步 effect 取消、旧请求覆盖、新 WS 快照恢复、subscription/EditorView cleanup 和多窗口隔离。

## 超出范围

- 跨来源 Wikilink、嵌入、内容引用、反向引用或标签关系；
- 在 Markdown 中持久化 `sourceKey:` 地址；
- 跨来源迁移、“移动到来源”、复制后自动删除原件；
- 复制后自动清理、重写或修复副本链接；
- 通过搜索结果、同名文件、Git、inode 或内容相似度猜测跨来源目标；
- 自动恢复 workspace UI、挂载、收藏、最近、全局任务视图和独立标签视图；
- 通用 IDE、动态查询语言、插件运行时、Lua/Widget 或数据库替代磁盘事实。

## 补充说明

### 已知风险与缓解

1. **同源资源地址重构跨多个文件。** 通过预览计划、版本快照、临时写入、提交顺序、失败注入和回滚日志降低半完成风险；计划提交前必须重新验证全部前置条件。
2. **多视图共享 CM6 历史。** 文档共享状态与视图状态必须明确分离，禁止复制富文本模型或在 Zustand 中保存 EditorView/DOM。
3. **外部文件事件乱序或丢失。** 资源事件只作为提示，重连和关键操作必须重新查询磁盘版本；客户端防止 stale response 覆盖新状态。
4. **超大目录和文档性能。** 使用懒加载树、可取消请求、增量解析、索引批处理、结果分页/限流和大小上限；不得在 Renderer 建立工作区级重复索引。
5. **跨平台文件系统差异。** 名称冲突、大小写、Unicode 规范化、符号链接、原子 rename、系统废纸篓和路径长度必须在三平台验证，不能用字符串模拟真实文件系统。
6. **来源暂时不可访问。** 区分“来源整体不可用”和“来源可访问但路径失效”；前者保留占位，后者清理失效标签，避免误删会话状态或重建文件。
7. **索引与磁盘短暂不一致。** 任何知识操作以 ResourceIO/磁盘版本为准；索引只提供候选、搜索和预览，提交前必须重新验证。
8. **第三方 Markdown 兼容。** 解析器以 CommonMark、GFM 和已确认扩展为基线；SilverBullet 兼容语法只在 ADR 已冻结范围内采用，不借机扩展私有方言。
9. **安全 HTML 和外链。** 使用集中净化策略、协议 allowlist、本地资产 scope 校验和显式外部打开；不在 Renderer 中自行拼接任意 URL 或文件路径。
10. **迁移与旧数据。** V1 不新增 workspace UI 恢复数据；索引、协议和回收站 manifest 仍需版本字段、幂等迁移、旧版本读取和损坏降级。

### 外部依赖与参考边界

- 当前项目仓库决定运行层、公开 API、构建、测试、open/full composition 和兼容边界；`NAMEWTA/HanaKDE` 只用于标识当前仓库来源。
- 本地 SilverBullet 源码 `./silverbullet/` 只用于研究 CodeMirror 6 extension 拆分、Live Preview decoration、Markdown 链接/Frontmatter/任务/表格/粘贴、状态与视图分离、受控空间接口及解析/索引模式。
- 任何来自 SilverBullet 的实现思路在采用前必须重新满足当前项目的 React、Hono、ResourceIO、Engine、独立 Server、权限和许可证要求。
- 不复制其产品外观、运行时、查询语言或插件模型，也不以动态依赖方式把其运行时代码引入 OpenHanako。

### 公开 API、协议与持久化影响

- 预计新增稳定的知识工作区复合操作、搜索、索引状态和回收站 DTO/错误码；通用文件 CRUD 继续使用现有 ResourceIO，不建立替代协议。
- 预计新增会话内 Renderer 文档/布局状态、Workbench 本地历史来源绑定、索引格式和回收站 manifest；UI 布局、标签、资源树展开/排序及挂载列表不跨 workspace 打开持久恢复。需要持久化的结构必须版本化并提供迁移。
- 预计扩展 Engine 公开 Facade 和 composition 注入，但不得让 route 访问私有状态，也不得让开放实现引用未开放代码。
- 预计需要最小原生能力扩展时，必须同步 main handler、preload bridge、参数 schema、类型声明、cleanup 和三平台测试。

### 完成定义

“完成”必须同时满足：

- `requirements-traceability.md` 中该 ticket 拥有的每个用户故事已有实现和列出的自动化证据。
- 该 ticket 拥有的 `KW-RULE-*` 契约测试通过。
- 失败、取消、冲突、权限和不可用路径已有自动化覆盖。
- 对应 E2E 场景在适用 project 通过；未适用必须有契约级原因。
- 实际命令与结果写入 ticket 交付记录，发布时汇总到 `release-evidence.md`。
- 不把普通执行记录写入设计 `LOG.md`。

### 完成定义（原有产品边界）

实现完成必须同时满足：

1. 文件资源管理器与 Markdown 编辑器覆盖本文全部 V1 用户故事和验收场景。
2. 普通文件操作复用现有 Workbench/ResourceIO/资源事件链路，复合操作仅通过公开知识工作区 Facade。
3. 同一页面多视图共享文档状态且视图状态独立；显式保存、冲突、关闭和恢复无数据丢失。
4. 同源移动/重命名链接重构原子，所有复制正文保持原样，删除/恢复可恢复且批次结果可解释。
5. 索引可从磁盘完全重建，超级搜索符合冻结词法、匹配、聚合和排序规则。
6. 所有外部输入经过校验，owner/scope/path 安全成立，日志和 DTO 不泄露敏感内容或任意绝对路径。
7. open/full boundary、独立 Server、Desktop、LAN、Mobile、五种语言、亮暗主题、键盘访问和三平台构建/测试通过。
8. 实际交付说明列出修改文件、分层理由、公开协议/持久化影响、安全与多平台影响、实际检查、未执行检查和残余风险。
