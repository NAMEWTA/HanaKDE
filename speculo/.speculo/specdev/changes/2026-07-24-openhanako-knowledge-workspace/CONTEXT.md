# OpenHanako 知识工作区上下文与领域词汇（唯一现行版）

本文件恢复本 change 最终讨论形成的完整领域语义：核心词汇用于跨层命名，细粒度词汇与 `_Avoid_` 保存已经接受的行为边界和禁止项。产品规则见 [`spec.md`](./spec.md)，架构决定见 [`ADR.md`](./ADR.md)，完整结论与理由见 [`LOG.md`](./LOG.md)。

## 使用与一致性规则

1. “核心规范词汇”提供当前仓库和跨层契约应优先使用的名称。
2. “完整领域词汇与行为边界”保留 318 个细粒度定义及 320 条 `_Avoid_`；它们不是草稿或已失效过程记录，而是 accepted LOG 的领域投影。
3. “实现精化术语”补充 2026-07-25 review 中为当前 HanaKDE 基座冻结的身份、事务、搜索、transfer 与原生能力词义；它只收紧编码边界，不推翻原有产品决定。
4. 同一概念存在旧称、细分称谓或界面称谓时，`规范化关系` 指向核心名称。名称归一不删除原定义中的行为、限制或错误边界。
5. ADR、CONTEXT、accepted LOG、Spec 与实施契约不得互相覆盖矛盾；发现冲突必须同步修正。具体交互由 accepted LOG/Spec 验收，精确 schema、算法和故障边界由实施契约编码。
6. 本地工程路径统一以仓库根目录为基准，SilverBullet 参考固定为 `silverbullet/`。

## 核心规范词汇

**Workspace**：用户当前活动工作根及其会话级附加来源组成的知识工作环境。

**活动工作根**：session 当前选择的 cwd 或 Studio `workspaceMountId` 对应根。

**main**：活动工作根在 Knowledge 协议中的固定 `sourceKey`。

**来源（Source）**：一个由 provider 控制、具有独立地址和索引域的文件空间。

**附加来源**：本次 workspace 会话中显式挂载、关闭后不自动恢复的额外来源。

**sourceKey**：来源的内部稳定路由键；不写入 Markdown。

**displayName**：来源的展示名称，不参与解析或身份判断。

**ResourceRef**：HanaKDE 既有的 provider 联合资源引用。

**KnowledgeResourceAddress**：由 `sourceKey` 与规范 `relativePath` 组成的知识协议地址。

**知识地址**：Markdown 中持久化的当前来源内规范相对路径。

**页面（Page）**：可使用 Markdown 知识语义编辑的真实 Markdown 文件。

**资产（Asset）**：除 Markdown 页面外的普通文件、未知文件或文件系统链接条目。

**磁盘已保存内容**：成功写入 provider 并可重新读取的页面正文或资产字节，是索引与 Server 查询唯一可持久依赖的知识事实。

**文档会话（Document Session）**：页面共享的 buffer、baseline、version、history 与 dirty 状态。

**文档视图（Document View）**：单个编辑组中的 cursor、selection、scroll 与 mode 状态。

**编辑组（Editor Group）**：承载一组 tabs 的可递归水平或垂直面板。

**临时预览标签（Preview Tab）**：可被下一次普通预览替换、固定后转为普通 tab 的视图。

**资源树**：按来源根分组、一比一投影 provider 真实文件与目录的可交互树；派生知识视图不伪装为真实目录节点。

**Live Preview**：同一 Markdown buffer 上以 decorations/widgets 隐藏或渲染语法的编辑模式。

**源码模式（Source Mode）**：显示完整 Markdown 标记的同一 buffer 视图模式。

**Wikilink**：`[[...]]` 或 `![[...]]` 形式的同源知识链接。

**Markdown Link**：标准 Markdown 链接；内部文件目标按引用页面目录相对解析。

**LinkResolver**：把页面上下文和链接词法结果解析为同源 `KnowledgeResourceAddress` 的纯领域服务。

**断裂引用**：在引用页面所属来源中无法解析的内部引用。

**内容引用**：带位置范围和持久显示快照的同源 Wikilink。

**嵌入（Embed）**：宿主页面内只读展示目标页面或章节的同源引用。

**Frontmatter 投影**：对同一 Markdown buffer 顶部 YAML 的保真可视化编辑层。

**标签（Tag）**：从 Frontmatter 或正文安全抽取、保存后进入来源分区索引的值。

**页面任务（Page Task）**：当前 Markdown 页面内的标准 `[ ]`/`[x]` 列表项。

**知识语义 IR**：跨 Renderer/Server 共享的文本范围、token 与规范化结果。

**来源分区索引**：只包含单一来源已保存磁盘内容的可重建派生存储。

**超级搜索（Super Search）**：同时查询当前来源集合、按来源分组并在组内排序的入口。

**操作计划（Operation Plan）**：提交前包含目标、预期版本、影响项与风险的不可变预览。

**操作提交（Operation Commit）**：使用 plan id 和 expected versions 执行复合操作的请求。

**OperationCorrelationId**：把 commit、ResourceEvent、watcher 和诊断摘要关联起来的标识。

**Checkpoint**：复合操作或编辑会话在失败恢复前保存的可验证恢复点。

**结构化批次结果**：逐项记录成功、失败、跳过和回滚状态的公开结果。

**悬空未保存文档**：来源丢失、资源被外部移除或 identity 暂时失效后，仍保留在 Renderer 中且尚未保存的文档会话。

**同源重构**：同一来源内 rename/move 的单一用户操作。持久事务边界包含主资源与已计划的同源链接文件；session identity、ResourceEvent 与索引是提交后必须幂等收敛、失败可重试的投影。

**跨来源复制**：把正文或字节原样复制到另一来源，不重写副本内部链接。

**工作区回收站**：每来源根级 `.trash/` 中由批次 manifest 管理的可恢复区域。

**系统废纸篓**：由操作系统提供的最终可恢复删除能力。

**内容门禁（Content Gate）**：在编辑、预览、渲染或索引前根据类型、编码、大小和安全策略做出的判定。

**Open composition**：不依赖闭源产品模块的共享 Server 组合根。

**Full composition**：在 Open 共享能力上注入 Desk 等完整产品能力的组合根。

**兼容 facade**：保留旧 URL/DTO 含义并把调用迁移到新共享契约的适配层。

**恶意工作区**：用于验证越界、主动内容、别名、TOCTOU 和资源耗尽防护的测试数据集。

**可审计适配**：记录第三方来源、哈希、许可义务、采用方式与目标实现的复用方式。


**ProviderRootIdentity**：provider 在 Server 内部返回的不可逆根身份与 scope token，用于证明来源真实根关系；不得进入远程 DTO 或日志。

**RootRelation**：两个 provider 根之间的 `same`、`ancestor`、`descendant`、`disjoint` 或 `unknown` 关系；只有 `disjoint` 可同时活动。

**Operation Journal**：复合 mutation 的持久 intent、步骤 outcome、checkpoint 引用与恢复状态；不保存正文或绝对路径。

**恢复屏障（Recovery Barrier）**：Server 暴露 Knowledge mutation route 前必须完成的未决 operation 扫描与恢复阶段。

**索引 Generation**：单一来源某一完整 schema/extractor 版本的 SQLite 索引实例。

**索引 Manifest**：以原子替换方式指向当前可查询 generation 的 Server 内部 `current.json`。

**NativeResourceGrant**：与 owner、window、action、KnowledgeResourceAddress 和 version 绑定的 60 秒单次 Electron 原生操作授权。

**原生能力矩阵**：当前客户端对 picker、系统剪贴板、默认应用、文件定位和系统废纸篓的明确可用性集合。

**Primary Requirement Owner**：对一条 `KW-US-*` 的实现与自动化验收负唯一责任的 ticket；Ticket 57 不能担任。

**Acceptance Evidence**：把 Requirement ID、owner ticket、实际测试命令、测试路径、平台和结果连接起来的发布证据。

**Implementation Preflight**：实现前对 Git、Node、package、关键接缝、依赖和 SilverBullet hashes 的可执行检查。

**Server 内部系统命名空间**：`<HANA_HOME>/knowledge-workspace/` 下的索引、journal、source binding 和证据目录，不属于用户来源或知识内容。

## 实现精化术语

**Provider Root Identity**：provider 在 Server 内给出的 `identityNamespace`、不透明根身份与 scope 证明，用于判定 same、ancestor、descendant、disjoint 或 unknown；不得进入远程 DTO、Renderer 或日志。
_Avoid_: 用 provider ID、用户输入路径字符串或 displayName 代替真实根关系证明

**文件事实事务边界**：复合 mutation 中必须一起成功或一起回滚的主资源和已计划用户文件写入。COMMITTED 后的 session、事件与索引更新是可重试投影，不反向撤销磁盘事实。
_Avoid_: 把 Renderer 状态、ResourceEvent 或 SQLite 瞬时更新宣称为跨层全局原子事务

**跨 Provider Transfer**：经 ResourceIO 在两个已授权 provider scope 之间以有界流、目录 staging 和原子发布完成的字节复制；它不向 Renderer 暴露路径，也不建立跨来源知识关系。
_Avoid_: Renderer 中转文件字节、全文件入内存、跟随 symlink、半目录发布、复制后自动删除源

**搜索折叠文本（foldSearchText）**：只为搜索匹配生成的 NFC 加 locale-neutral lowercase 派生文本；不移除变音符，也不改变真实文件名、地址、正文或展示字符。
_Avoid_: accent folding、路径身份大小写折叠、把索引折叠文本写回知识文件

**Native Bridge Credential**：Desktop-owned Server 每次启动生成、只在 Electron Main 与本地 Server 之间使用的 Main-only 凭据；它与一次性 NativeResourceGrant 分工，永不进入 Renderer、preload DTO、事件或日志。
_Avoid_: 复用 Renderer 可见普通 token、把凭据暴露为 IPC getter、用长期凭据替代一次性资源授权

**认证 Principal**：由 Server 已认证 Hono context 提供的 owner/user/studio 身份。公共 body 中同名或近似身份字段必须被 schema 拒绝，不能覆盖认证上下文。
_Avoid_: 信任客户端提交的 principal、ownerId、userId 或 studioId

**多 Renderer Context 隔离**：Server、session、订阅、异步投影和 native grant 对现有桌面生命周期、异常恢复或自动化产生的多个 Renderer context 保持 owner/window 隔离。
_Avoid_: 把并发安全要求解释成 V1 新增独立浮动知识窗口、标签脱离窗口或“新建知识窗口”产品入口

## 完整领域词汇与行为边界

**工作目录**：
用户当前选择并允许 OpenHanako 使用的真实本地目录；它同时就是 OpenHanako 当前唯一 workspace 的 `main`。更换工作目录等同关闭旧 workspace 并打开一个全新 workspace。
规范化关系：核心术语归一到「活动工作根」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 与 workspace 分离的目录设置、可热替换 main、知识库目录、书桌目录

**知识工作区**：
以当前工作目录作为唯一 `main`，并在当前会话中接入零个或多个额外挂载源的知识管理空间。工作台工作目录、知识 workspace 与 `main` 是同一逻辑概念；切换工作目录会卸载全部旧挂载并创建全新 workspace。
规范化关系：核心术语归一到「Workspace」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 与工作目录并列的第二 workspace、热重绑 main、自动继承挂载、独立知识目录、Obsidian Vault

**V1 核心范围**：
知识能力第一阶段的交付边界，以文件资源管理器和 Markdown 编辑器为两大核心；基础超级搜索保留，但可视化筛选器、任务高级元数据及其他增强工具延后到后续版本。
规范化关系：本词条保留为直接有效的细粒度领域定义；其行为由 `spec.md` 与相关 ticket 验收。
_Avoid_: 完整知识管理套件、V1 搜索增强平台、V1 任务系统、功能面平均铺开

**主来源 `main`**：
当前工作目录在知识 workspace 中的唯一主来源。其内部 `sourceKey` 固定为 `main`。`main` 是独立内容来源；其中 Markdown 的 Wikilink 只能指向 `main` 内资源。
规范化关系：核心术语归一到「main」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 可热重绑定主根、由挂载提升为 main、在 Markdown 中写 `main:`、默认挂载

**挂载源**：
在当前 workspace 会话中接入的额外目录。每个挂载源拥有内部 `sourceKey` 与展示用 `displayName`，但它与 `main` 及其他挂载源在文件空间、知识地址、链接图、反向引用和标签语义上彼此隔离。挂载用于浏览、搜索、编辑和复制，不提供跨来源直接引用。
规范化关系：核心术语归一到「附加来源」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 子知识库合并、跨来源 Wiki、自动恢复挂载、重叠目录、提升为 main、扁平命名空间

**知识地址**：
Markdown 中用于 Wikilink、嵌入与内容引用的来源内规范相对路径，例如 `Projects/A.md`。解析根固定为包含该 Markdown 文件的来源；地址不包含 `sourceKey`，也不能越过来源根。应用内部跨层定位另用 `KnowledgeResourceAddress` 表达 `{sourceKey, relativePath}`，再由 Server 来源注册表解析为既有 `ResourceRef`。
规范化关系：核心术语归一到「知识地址」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: Markdown 中的 `sourceKey:`、绝对路径、跨来源 URI、最短唯一文件名、全局同名猜测

**来源键 `sourceKey`**：
内容来源在 Workbench、ResourceIO、DTO、打开会话与搜索分组中的稳定路由键，格式为 `[a-z][a-z0-9-]{0,31}`，`main` 为保留值。它不写入 Markdown Wikilink，也不参与来源内链接解析。
规范化关系：核心术语归一到「sourceKey」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: Markdown 地址前缀、displayName 作为身份、Unicode key、静默冲突后缀

**来源显示名称 `displayName`**：
来源在界面中的可变名称，只用于展示和未保存文档识别；不参与 Markdown 地址、引用解析或组内搜索排序。
规范化关系：核心术语归一到「displayName」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 知识地址前缀、稳定身份、链接目标、排序事实

**历史来源绑定**：
Workbench 本地配置保存的来源根与 `sourceKey`、`displayName` 关系，只在用户显式重选 provider 能证明完全相同的根时复用，不自动挂载。若 key 已占用则阻止挂载，用户选择新的未占用 key，或先卸载/重命名占用来源。
规范化关系：核心术语归一到「来源」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 自动挂载、启发式根识别、自动 key 后缀、原子 key 交换、正文迁移

**来源身份重新分配**：
对 Workbench 内部来源路由键的显式修改。V1 只允许在 key 未占用且来源无未保存缓冲区时提交；打开的干净资源同步更新内部 `KnowledgeResourceAddress`。该操作不扫描或修改文件正文，因为 Markdown 引用从不包含 `sourceKey`。
规范化关系：核心术语归一到「sourceKey」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 跨来源链接迁移、批量 Wiki 重写、原子交换两个占用 key、修改 Markdown 地址

**规范相对路径**：
由 ResourceIO/provider 在来源 scope 内验证的真实相对路径。协议层路径分隔符固定为 `/`，保留大小写与 Unicode 序列；拒绝 `.`, `..`、绝对路径、盘符、UNC、空路径段，以及把原始反斜杠当作替代路径分隔符。provider 若允许文件名段包含字面反斜杠，则该字符只能作为已验证名称段并通过 Wikilink 词法转义表示。
规范化关系：核心术语归一到「KnowledgeResourceAddress」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 大小写折叠、Unicode 规范化、百分号隐式解码、字符串拼接越界

**来源根不重叠**：
同一 workspace 中 `main` 与所有挂载源的真实根路径不得相同、互为祖先/后代，或通过符号链接、Junction、挂载点、大小写别名指向重叠区域。无法证明互不重叠时拒绝挂载。
规范化关系：核心术语归一到「来源」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 仅比较输入字符串、允许嵌套挂载、乐观接受未知别名

**页面**：
知识工作区中可作为链接目标和编辑单元的 Markdown 文件；其身份由所在来源与规范化相对路径共同确定。
规范化关系：核心术语归一到「页面」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 笔记 ID、文档 UUID、永久页面 ID

**页面标题**：
页面文件名去除 `.md` 扩展名后的名称；页面标题直接来自文件名，不存在独立标题属性或别名。它用于页面正文语义、页面选择器的展示文字以及整页 Wikilink 的显示，不替代资源身份界面中的完整文件名。
规范化关系：核心术语归一到「页面」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: Frontmatter title、资源树文件名、编辑器标签名、页面别名、独立笔记名

**页面身份**：
页面在某一时刻的应用内部身份，即 `{sourceKey, 规范相对路径}`；Markdown 内部引用只保存该页面在当前来源内的规范相对路径。
规范化关系：核心术语归一到「KnowledgeResourceAddress」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 隐藏 UUID、跨来源 Markdown 地址、文件名全局身份

**页面属性**：
以页面顶部 YAML Frontmatter 持久化的结构化页面元数据；实时预览提供可视化编辑，源码模式保留真实 YAML 原文。`title` 与 `aliases` 即使存在也只按普通属性处理，不改变页面标题或链接解析。
规范化关系：核心术语归一到「Frontmatter 投影」；本词条继续提供完整行为边界与 _Avoid_ 约束。
_Avoid_: 行内属性、数据库属性、隐藏元数据、特殊 title、页面别名

**标签**：
用于分类页面或标记正文上下文的知识标记；标签可以来自 Frontmatter `tags` 或正文 `#tag`，两者合并进入页面所属来源的可重建标签索引，并在同一页面内按标签值去重。点击正文标签会打开预填查询且明确显示当前来源固定 scope 的超级搜索；该 scope 不是通用来源筛选器。
