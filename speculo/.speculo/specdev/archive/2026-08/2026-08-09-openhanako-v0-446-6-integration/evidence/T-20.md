## 1. 实现摘要

Knowledge source rereads now route Office/PDF resources through the T-19
`DocumentExtractionService`, project the returned derived Markdown through the
existing Markdown Semantic IR extractor, and retain the original Office path
and resource kind in the source-partitioned index. The resource version and
T-19 extractor version are combined into the document version token, and a
post-extraction ResourceIO stat rejects a version race before publication.

Legacy product adapters now release their Materialize lease in a `finally`
block; PDF `maxPages` explicitly remains on the page-range adapter path.

Incremental indexing now accepts extracted Office/PDF facts whose authoritative
resource kind remains `binary`/`pdf` while derived Markdown supplies page and
heading structure. Non-indexed or page-less resources still fail closed. This
aligns event-driven writes with the already-valid full rebuild contract.

The Office plugin accepts the same canonical extraction port for full reads of
authorized resource refs. HTML DOCX, structured XLSX JSON, and PDF page-range
responses remain product adapters; legacy absolute `filePath` callers retain
their existing local-only behavior. No derived Markdown resource is written.

## 2. 修改范围

### Feature placement decision

This capability belongs to the system core: it changes the privileged
Knowledge ingestion/index contract, owns source generation and extractor
version invalidation, and must be driven by the main/mount ResourceIO event
pipeline. The Office plugin remains a format-specific adapter contribution for
HTML/JSON/page-range output and consumes the shared service; it does not own
Knowledge state, watchers, or indexing.
