## 1. 实现摘要

新增 macOS-only gate runner 与 Vitest contract，严格要求 `darwin`，在真实 arm64 主机上创建临时 workspace 并验证递归 `fs.watch`、rapid edits、atomic replace、大小写别名、symlink escape、root identity replacement 和 SIGSTOP/SIGCONT suspend/resume。Runner 还可检查 Electron `.app` 中的 signed seed tar，确认 server bundle、AnyDoc child、HTML child 与目标架构 secure helper 均存在。后续修正让 macOS real-matrix spec 在非-Darwin 仅 skip，并新增不创建 fixture 的 fail-closed guard，避免 T-25 在 Windows 合并运行时被 macOS spec 自身误阻断。

Commit `99b6a993` adds a permanent packaged direct-flow runner and contract. It verifies the supplied DMG, mounts it read-only, copies one app into a disposable sandbox, optionally ad-hoc signs only that copy, launches the real packaged app without an unsafe `--no-sandbox` argument, and runs Office edit/re-extraction/restore/search, visible History diff/UI restore/read-back after renderer reload, Agent write/receipt/replay/reload/History, and `@` search/select/Escape. The deterministic provider import is rewritten only inside the isolated package artifact under the disposable `HANA_HOME`; cleanup reports app/server stop, DMG detach and sandbox disposal.

Integration checkpoint `2b0ef66b` 进一步加入隔离的 production-workspace child probe。该 probe 组合真实 legacy `ResourceWatchRegistry`、production cutover/coordinator、`ResourceEventBus`、shared baseline 与 `KnowledgeIndexRuntime`，并在真实 native callback 上确定性抑制一次 `Lost.md` 事件，再从实际 product listener 注入 gap。结果证明 legacy close-before-coordinator-open、峰值单一 `FSWatcher` lease、`HEALTHY -> DEGRADED -> RECONCILING -> HEALTHY`、丢失项只经 shared baseline 进入 Knowledge，以及修复后的正常 provider-watch event 继续收敛。此为 FSWatcher lease accounting 与 deterministic product gap contract，不冒充 literal kernel descriptor count 或 physical sleep/wake。

本 Ticket 只增加平台 harness，不修改共享 package、产品代码、native source 或 release/signing 配置。临时 app 重签仅用于本机 unsigned smoke，未写入仓库。

## 6. 残余风险与后续

- `macOS x64` runtime and cross-arch DMG remain unverified on this arm64 host. The standalone native helper cross-compile now passes, but `arch -x86_64` execution is unavailable; T-23 is not a universal macOS platform sign-off until the runtime/package matrix runs.
- Hardware sleep/wake and actual event loss/reconcile require a sleep-capable platform runner; SIGSTOP/SIGCONT is only the deterministic process-lifecycle probe.
- Current dev Electron/Web Open Office and desktop History/Agent flows pass. The arm64 package rebuilt at package checkpoint `4c6aa5ce` from product `feb906d6` and quality `8aa9f7b1`, then exercised by the committed runner at `99b6a993`, also passes packaged Office, visible Workbench History, T-26 Agent write/replay/History and `@` search/select/Escape after artifact-only ad-hoc re-sign. Production signing/notarization remains unproved as an explicitly out-of-scope release concern; no release signature claim is made.
- The production probe now proves attributable native `FSWatcher` lease ownership/cleanup and product-level deterministic gap/reconcile on macOS arm64. It still does not prove literal kernel descriptor counts or physical hardware sleep/wake with naturally lost events; SIGSTOP/SIGCONT and injected product-listener gap are not substitutes for those rows.
- The pre-adapter launch probe emitted renderer-side `event-bus` subscriber errors because the external todo plugin used the declared type-first `bus.subscribe(eventType, handler)` overload while `<Path>core/plugin-context.ts</Path>` forwarded only callback-first arguments to `<Path>hub/event-bus.ts</Path>`. Approved deviation D-T23-02 adds the bounded plugin-boundary adapter in `<Path>core/plugin-context.ts</Path>` with regression coverage in `<Path>tests/plugin-context.test.ts</Path>`; the 140-test suite and targeted typecheck pass. A current packaged relaunch copied that exact todo `0.0.5` plugin into an isolated temporary `HANA_HOME`: the plugin loaded and activated on startup, registered its route/tools, emitted no event-bus subscriber errors, and unloaded cleanly. Its optional task-handler requests reported the documented unavailable-capability warnings and degraded safely; they are unrelated to the repaired bus overload.
