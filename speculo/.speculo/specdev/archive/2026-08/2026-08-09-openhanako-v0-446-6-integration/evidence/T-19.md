## 1. 实现摘要

Document extraction now accepts only authorized ResourceIO input. It performs bounded direct reads through `openRead`, falls back to a Materialize lease only when direct reading is unavailable or denied, detects content bytes before filename or staging-path hints, isolates Anydoc and HTML conversion in short-lived children, bounds derived Markdown, and returns the Ticket's stable failures. File Tool receives the session sandbox ResourceIO only through the approved object-identity check for the built-in File Tool.

The correction pass has three High fixes:

1. It removes the extraction-layer `ResourceIO.read` fallback, rejects a read-only ResourceIO at construction, and makes denied or absent `openRead` fall back only to Materialize; direct-only denial returns stable `parse-failed`.
2. It reads Materialize leases through a `FileHandle` in 64 KiB chunks bounded by `MAX_INPUT_BYTES + 1`, detects materialized bytes before extension/path inference, and rejects stale-stat oversize before a converter runs.
3. It starts and releases an oversized direct async body before returning and rejects oversized chunks before `Buffer.from()` copies them, closing the LocalFs descriptor-leak path.

The focused correction loop first produced five red regressions, then reached 33 green ResourceIO extraction tests; the final focused cross-boundary suite is 9 files and 94 tests green.
